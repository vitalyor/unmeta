# Unmeta — спецификация интерфейса (направление E «Фото и текст»)

Выбрано владельцем 2026-11-05. Этот файл — задание для MVP в `src/` (Svelte 5). Живой эталон: `design/mockups/e-photo.html`, все экраны переключаются панелью «Макет» внизу. Токены лежат в `design/tokens.css`, обоснования — в `design/RESEARCH.md` (разделы 10–12).

## 1. Принципы
1. **Главное — фото человека.** Его превью показываем крупно и строим прямо на устройстве (`URL.createObjectURL`), в сеть ничего не уходит.
2. **Найденное — текстом рядом**, без наклеек поверх фото. Длинные значения переносятся и никогда не обрезаются «…».
3. **Одно главное действие на экране:** «Очистить», «Скачать»/«Сохранить» или «Выбрать». На телефоне оно в доке под большим пальцем.
4. **Меньше текста на виду, подробности по запросу.** Описание видно только у выбранного режима, теги — в «Подробном списке».
5. **Движение отвечает на действие.** На экране один главный анимационный момент, только `transform`/`opacity`, а при «Уменьшить движение» всё срабатывает мгновенно.
6. **Ни одного эмодзи.** Только иконки Lucide (inline SVG), рядом всегда подпись.

## 2. Сетка и адаптивность
| Ширина | Раскладка |
|---|---|
| ≤ 640 px (телефон) | Одна колонка. На ≤ 440 px «чип» режима в доке показывает только значок (название остаётся в `aria-label`), чтобы главная кнопка («Очистить 8 файлов») помещалась целиком. Главное действие в **доке** снизу (`position: sticky`, `safe-area-inset-bottom`, сплошной фон без `backdrop-filter`). Режимы — в **нижней шторке**. Фото на отчёте высотой `min(34vh, 260px)` |
| 641–999 px (планшет) | Одна колонка, фото `min(42vh, 440px)`. Кнопки в строке под заголовком, режимы — в шторке |
| ≥ 1000 px (компьютер) | Две колонки: фото слева (остаётся на месте при прокрутке, `position: sticky`), справа заголовок, режимы (видны всегда), кнопка и список |
| 2560 px и больше | Та же раскладка, ширина ограничена `--maxw: 1280px`. Корневой шрифт растёт до 20 px, поэтому всё чуть крупнее, но не растянуто |

Боковые поля `--gutter: clamp(16px, 4vw, 56px)`. На ширине 320 px горизонтальной прокрутки нет (это проверяет `design/tools/smoke.mjs`).

## 3. Экраны и состояния
Ключи текстов взяты из `copy/ru.json` и `copy/en.json`.

| Экран | Когда | Что на экране | Главное действие |
|---|---|---|---|
| **Старт** | Открыли сайт | `start.title` (Unbounded), `start.subtitle`. Фото-пример и **этикетка** поверх его нижнего края: «Где снято / Телефон / Когда / Автор» со значениями под маркером (на телефоне 3 строки). `start.privacy` со ссылкой и `start.whatIsHidden` (раскрывается). Ссылка «Попробовать на примере» (`start.tryExample`) | Компьютер: «Выбрать файлы» (`start.choose`), перетаскивание на всю страницу. Телефон: «Выбрать фото и видео» (`start.chooseMedia`) открывает системную галерею (`accept="image/*,video/*"`, `multiple`) и ссылку «Документы и другие файлы» (`start.chooseDocs`) (все типы) |
| **Загрузка инструмента** | Первое видео или аудио, ffmpeg ещё не загружен | Файл, `progress.loadingTool` {size}, `progress.loadingToolHint`, прогресс в процентах и МБ | «Отмена» |
| **Отчёт** | Один файл прочитан | Фото и строка «имя · размер». `report.title`, `report.summary` {count}, режимы, «Очистить». Карточка-список находок: значок, фраза `categories.*.found` {state}, значение под маркером, `categories.*.why`. Затем `report.alwaysKept` и `report.details` (таблица полей) | «Очистить» (`actions.clean`) |
| **Режимы** | Компьютер: всегда видны. Телефон и планшет: шторка по кнопке-«чипу» с названием режима | Плитки 2×2 (значок + `modes.*.name`), под ними `modes.*.for` выбранного режима, `modes.remembered`. «Что убрать» (`modes.custom.heading`) — девять галочек, видны в любом режиме. Сняли или поставили галочку — режим становится «Свой», появляется тост `modes.custom.switched` | — |
| **Очистка** | Нажали «Очистить» | Прогресс растёт прямо в кнопке, по фото бежит полоса света. Если дольше ~2 с — `progress.cleaning` → `progress.verifying` | — |
| **Было / Стало** | Готово | `result.done`, `result.verified` или `result.verifiedKept`. Кнопка получения файла, `result.newName` {name}, `result.originalSafe`. Переключатель `result.before` / `result.after`. Список: в «Стало» значения зачёркнуты и приглушены, значок — зелёная галочка, рядом `result.removed`. Затем `result.leftover` и «Начать заново» | Компьютер: «Скачать». Телефон: «Сохранить» — системное меню «Поделиться» (`actions.saveHint`). Без автоскачивания |
| **Пакет** | Выбрано несколько файлов | Галерея плиток (фото квадратом, у видео значок ▶). Под плиткой имя, размер и статус текстом: «Есть геопозиция · N находок» (`batch.hasLocation`, `batch.findings`), `batch.nothingHidden`, `batch.cantClean`. Заголовок: `batch.files` и сколько файлов с геопозицией | «Очистить N файлов» (`actions.cleanCount`). Потом у каждой плитки «Скачать» и общее «Скачать всё» (`actions.downloadAll` + `actions.downloadAllHint`) |
| **Ничего не нашли** | Файл уже чистый | `report.nothingFound`, `report.nothingFoundHint`, `report.alwaysKept` | «Добавить ещё» |
| **Текстовый файл** | txt, md, csv, json | `plainText.title`, `plainText.body` | «Выбрать другой файл» (`actions.chooseOther`) |
| **Не умеем** | Неизвестный формат | `unsupported.title`, `unsupported.body`, `unsupported.format` {ext}, `unsupported.tip` | «Выбрать другой файл» (`actions.chooseOther`) |
| **Большой файл** | Выше мягкого порога устройства | `bigFile.title` {size}, `bigFile.body` → «Попробовать» → прогресс: этап (`progress.reading` / `progress.cleaning` / `progress.verifying`), крупные проценты, `progress.of`, `progress.left` / `progress.leftMinutes`, «Отмена» | `bigFile.try` / `bigFile.skip` |
| **Слишком большой** | Выше потолка WASM | `tooLarge.title` {size}, `tooLarge.body` {limit}, на телефоне `tooLarge.mobileHint` | «Выбрать другой файл» (`actions.chooseOther`) |
| **Ошибка** | Сбой очистки или нехватка памяти | `errors.title`, текст из `errors.*`, `result.originalSafe` | «Попробовать ещё раз» (`actions.retry`) |

## 4. Компоненты
- **Фото** — `aspect-ratio: 4/3`, `--r-photo`, `--shadow-photo`, `object-fit: cover`. Если превью построить не удалось (HEIC в Chrome), показываем значок типа файла. При переходе старт → отчёт → готово фото «перелетает» (View Transitions, `view-transition-name: photo`).
- **Этикетка (старт)** — карточка `--surface`, наложена на низ фото (−64 px, на телефоне −36 px). Строки «ключ | значение» (на телефоне ключ над значением), значение под маркером `--mark` с `box-decoration-break: clone`, поэтому корректно переносится.
- **Строка находки** — значок 36 px в плитке `--r-icon` (у геопозиции фон `--warm`), фраза 600, значение под маркером, пояснение `--muted`. Однострочный маркер — это один элемент с `scaleX`. Если значение переносится, маркер становится фоном строки текста (без анимации ширины).
- **Плитка режима** — 58 px, значок 32 px. Выбранная: фон `--accent-soft`, обводка 2 px `--accent`, значок «пружинит».
- **Галочка категории** — 22 px, отмечается с пружинкой. Подпись «Убрать: …» (`modes.custom.toggleLabel`) читает программа чтения с экрана.
- **Главная кнопка** — «пилюля» высотой 56 px, `--accent`. При нажатии `scale(.965)`. Во время очистки прогресс растёт внутри кнопки (`scaleX` подложки). После «Скачать» кнопка становится «Сохранено» с галочкой (`--ok`).
- **Переключатель «Было / Стало»** — `role="tablist"`, подвижная «пилюля» переезжает за 380 мс.
- **Шторка (телефон, планшет)** — снизу, скругление 30 px, ручка сверху, затемнение `--scrim`. Готовый режим выбирается касанием, и шторка сама закрывается. Режим «Свой» оставляет её открытой.
- **Плитка галереи** — квадрат с радиусом 22 px. Во время очистки внизу плитки полоса прогресса, после — круглая кнопка скачать (44 px) в углу.
- **Карточка-сообщение** — до 620 px шириной, радиус 32 px, по центру. Прогресс: полоса 12 px, проценты крупно шрифтом Unbounded.
- **Тост** — снизу, тёмный, `aria-live="polite"`, исчезает через 3,2 с.
- **Шапка** — знак и «Unmeta» (Unbounded 600), справа RU/EN и тема (по 44 px).

## 5. Движение
| Событие | Что происходит | Время / кривая | При «Уменьшить движение» |
|---|---|---|---|
| Смена экрана | View Transition: старый экран уходит (180 мс), новый поднимается на 10 px (320 мс). Фото перелетает | `--ease-out` | Без перехода |
| Старт | Заголовок поднимается, строки этикетки появляются по очереди | 700 мс, ступень 110 мс | Сразу на месте |
| Отчёт | Маркер проходит по каждому значению слева направо | 450 мс, ступень 80 мс | Маркер сразу на месте |
| «Очистить» | Прогресс в кнопке и полоса света по фото | по реальному прогрессу; полоса 1,1 с | Без полосы |
| Готово | Маркер уходит вправо, как ластик, значение гаснет и зачёркивается, значок → галочка (пружина), полоса света по фото | 450 мс + 350 мс, ступень 110 мс | Сразу итоговое состояние |
| «Было / Стало» | Маркеры и зачёркивание возвращаются или уходят, «пилюля» переезжает | 380–450 мс | Мгновенно |
| Режим / галочка | Плитка и значок «пружинят», тост | 250–420 мс | Мгновенно |
| Перетаскивание | Фото чуть увеличивается, появляется пунктирная рамка | 350 мс | Только рамка |
| Нажатие | `scale(.965)` | 140 мс | Нет |

Анимируются только `transform` и `opacity`. Ширину, высоту, `top` и фильтры не анимируем. Прогресс — CSS-переменная `--p` в `scaleX`, её обновляет `requestAnimationFrame`. Критерий из брифа (60 fps на бюджетном Android) проверяем в MVP.

## 6. Доступность
- Контраст всех пар ≥ 4,5:1 в обеих темах (`python3 design/tools/contrast.py`). Цвет не единственный носитель смысла: всегда есть текст или значок.
- Видимый фокус (2 px `--accent`). Зона загрузки — кнопка (Enter/Space). Режимы — `radiogroup`. Прогресс — `progressbar` с `aria-valuenow`. Статусы и тосты — `aria-live`.
- Иконки: `aria-hidden="true"`, у кнопок из одной иконки — `aria-label`.
- Цели касания ≥ 44 px (главные кнопки 56 px), промежутки ≥ 8 px. Ничего не держится только на наведении.
- Русская типографика: короткие слова (в, о, и, на, не…) приклеены неразрывным пробелом. Кавычки «ёлочки», буква «ё».

## 7. Ресурсы
- **Шрифты:** Onest (вариативный 400–700) + Unbounded 500, OFL 1.1, свои woff2 (латиница и кириллица, примерно 48 + 35 КБ). Unbounded используется только в главном заголовке, бренде и крупных числах.
- **Иконки:** Lucide 1.69.0 (ISC). Карта «ключ → иконка» — `design/tools/build_icons.py` (`location → map-pin`, `device → smartphone`, `dates → clock-3`, `author → user-round`, `software → pencil-line`, `thumbnails → image`, `descriptions → message-square-text`, `c2pa → badge-check`, `filename → tag`, режимы `shield / scale / eye-off / sliders-horizontal`, действие `eraser`). Встраиваются при сборке, лицензию сохраняем.
- **Фото для «Попробовать на примере»:** в макете пёс с Unsplash (`mockups/photos/CREDITS.md`). В продукте лучше свой снимок с заранее известными метаданными: он же пригодится как тестовый файл.

## 9. Чего макет не решает
- **Превью HEIC/HEIF** в браузерах без поддержки (Chrome, Firefox): превью придётся строить движком, иначе показываем значок. **Кадр для видео** — первый кадр через `<video>`, если браузер умеет формат.
- **Реальный прогресс** придёт из движка (ExifTool / ffmpeg), в макете он имитирован.
- **Порог «большого» файла** берётся из замеров прототипа (бриф, раздел «Большие файлы»).
- **«Поделиться» на iPhone** — через Web Share API с файлом. Проверить на реальных устройствах.
