# Unmeta — бриф

Сайт, который удаляет метаданные из файлов прямо в браузере. Открыл ссылку на любом устройстве, закинул файл, получил чистый. Ничего не устанавливается, файлы не покидают устройство.

Решения приняты 2026-11-05.

## Продукт
- Качество публичного коммерческого продукта; пока хостим для себя и близких (GitHub Pages).
- Код открытый, лицензия **AGPL-3.0**.
- Интерфейс **RU + EN**, язык по браузеру, переключатель в углу. Все тексты в словарях с первого дня.
- Просто сайт: без установки/PWA-манифеста. Service worker — только как кеш ради скорости повторных визитов.

## Приватность
- **Сервера нет.** Ни одного сетевого запроса с файлами или данными о них. Проверяется вкладкой Network.
- О файлах не хранится ничего, даже локально. Помним только настройки: режим, галочки «Своего», язык, тему.
- Геопозиция: город/карту не определяем. Пишем «📍 Есть точная геопозиция — будет удалена». Цифры — только в подробном списке тегов.

## Форматы и движки
Охват широкий: все популярные фото, видео, аудио, документы.

| Движок | Что делает | Вес (gzip) |
|---|---|---|
| Image::ExifTool 13.42 в zeroperl (`@6over3/zeroperl-ts`), один долгоживущий Perl в воркере | **Чтение** для отчёта; **очистка** фото: JPEG, HEIC/AVIF, PNG, WebP, TIFF, GIF; RAW — только точечно | 7,2 МБ |
| ffmpeg.wasm (`@ffmpeg/core` 0.12.10), только при первом видео/аудио | **Очистка всего видео и аудио**, включая MP4/MOV/M4A: remux без перекодирования; дополнительное чтение тегов, которых не видит ExifTool | 9,7 МБ |
| pdf-lib | PDF: полная пересборка + сборка мусора (иначе старые объекты остаются в файле), чистка вставленных фото и авторов аннотаций | мало |
| Свой модуль | DOCX/XLSX/PPTX, ODT/ODS/ODP: свойства, комментарии/правки, rsid, миниатюры, вставленные фото, даты zip; SVG | мало |
| «Встроенных метаданных нет» | txt, md, код, csv, json и прочий plain text | — |

- Неизвестный/неочищаемый формат — **дружелюбный отказ**, никогда не говорим «чисто», если не уверены.
- После очистки движок **всегда перечитывает результат**; если что-то из удаляемого осталось — ошибка, а не «готово».
- Как узнавать о неподдержанных форматах — **отложено**.

### Движок v1 (2026-11-05) — `src/engine/`, тесты `test/` (50/50 в Chromium + WebKit)
- Фото: 20–200 мс на файл вместе с проверкой «до/после» (было ~800 мс: Perl теперь не перезапускается на каждый файл).
- Видео 258 МБ: **1,4 с** (Chromium) / **2,0 с** (WebKit) — чтение + очистка + проверка; вход читается через WORKERFS без копии в память.
- Тесты: 21 файл с подложенными секретами; проверяется, что ни одной строки-секрета не осталось нигде в файле (включая zip и сжатые потоки PDF), что файл открывается нативными ffmpeg/sips, ориентация фото и поворот видео на месте, режимы оставляют ровно своё.
- Видео/аудио: удаляются data-дорожки (телеметрия GoPro/DJI/iPhone с GPS) и в MP4/MOV — субтитры (у дронов там GPS). Обложки (cover art) пока остаются.
- В «Своём» для видео/аудио пока можно оставить только даты, автора и описания; геопозицию/устройство движок удаляет и сообщает об этом (`av-cannot-keep`).
- RAW (проверено на 8 реальных камерах: iPhone 12 Pro, Pixel 8 Pro, Canon R5, Sony A7 V, Nikon Z6 III, Fuji X-M5, OM-5 II, Panasonic G9 — `test/fetch-samples.sh`, `test/samples.test.ts`): удаляются **ровно найденные** личные теги, по одному, в два прохода; что нельзя удалить — обнуляется. Целиком группы не трогаем: удаление GPS-блока ломает Canon CR3 (`GPSVersionID` обязателен). Make/Model/структура MakerNotes/превью остаются.
- RAW, что форматы не дают тронуть (честно показываем в отчёте, `raw-kept:`): даты и версия приложения в MakerNotes Pixel/Canon/Nikon; серийник Nikon (ключ к зашифрованному балансу белого — без него «поедут» цвета) и Panasonic. Местоположение, автор, описания — удаляются всегда.
- C2PA: JPEG — удаляется в «Максимальном», сохраняется в «Сбалансированном» (через «удалить всё, кроме JUMBF»). PDF — манифест-вложение (`/AF`) удаляется, обычные вложения остаются. MP4 — удаляется ремуксом; оставить C2PA в видео пока нельзя.
- Цветовой профиль (ICC) не считается утечкой: его «устройство/дата» — это паспорт профиля (sRGB 1998), а не человека.
- PDF с подписью: пересборка ломает цифровую подпись — нужно предупреждение в UI. Зашифрованный PDF → ошибка `pdf-encrypted`.
- Большой видеофайл в 8-ГБ-телефоне и бюджетном Android — проверить на эмуляторе.
- Личные тестовые файлы класть в `test/private/` (в `.gitignore`).

### Результаты прототипа (2026-11-05, Chrome 152, Mac)
- ExifTool чистит JPEG/HEIC/PNG/GIF полностью, ориентация сохраняется. TIFF — только с явным удалением тегов IFD0 (Make, Model, Artist, Software, Copyright, ImageDescription…).
- ExifTool **в браузере ~0,7–1 с на файл** даже для крошечных (запуск Perl на каждый вызов). Пакет из 50 фото ≈ 40 с — нужно ускорять: несколько файлов за один вызов, параллельные воркеры или свой быстрый стриппер для JPEG/PNG.
- ExifTool **запись большого видео — неприемлемо**: 271 МБ MP4 → 9+ минут и 11,7 ГБ памяти. Поэтому всё видео идёт через ffmpeg.
- ExifTool **чтение** 271 МБ, если передать `File` (а не байты), — 0,1 с.
- ffmpeg.wasm: 271 МБ MP4 → **0,35 с**. MOV/MP4 с GPS Apple (Keys), автором, XMP — всё удалено, даты обнулены, поворот сохранён. Остаётся только безобидное «Lavf»/длительность.
- pdf-lib: PDF чистится за ~10 мс, в файле не остаётся строк с автором/программой. ExifTool пишет PDF дописыванием в конец (старое восстановимо) и в WASM-сборке PDF всё равно падает (нет модуля Perl `mro`).
- Баги библиотеки: в Web Worker zeroperl принимает браузер за Node и ищет wasm по неверному пути. Обходится шимом + своим `fetch` — в проекте сделать патч и отправить исправление автору.
- ffmpeg держит файл в памяти целиком (heap ≈ размер файла). Для больших файлов на телефоне — монтировать вход через WORKERFS (без копии), проверить.
- Хостинг: проверить, сжимает ли GitHub Pages `.wasm`. Если нет — это 25 + 32 МБ без сжатия; тогда Cloudflare Pages (brotli: 5,1 + 6,9 МБ).

## Очистка
Ориентация, цветовой профиль (ICC) и поворот видео сохраняются **всегда**.

| Категория | 🛡 Максимальный (по умолч.) | ⚖️ Сбалансированный | 📍 Только приватное |
|---|:-:|:-:|:-:|
| Местоположение | стереть | стереть | стереть |
| Устройство и серийники | стереть | стереть | стереть |
| Автор и копирайт | стереть | стереть | оставить |
| Программы и история правок | стереть | стереть | оставить |
| Встроенные превью | стереть | стереть | оставить |
| Даты | стереть | оставить | оставить |
| Описания и подписи | стереть | оставить | оставить |
| Подписи подлинности (C2PA) | стереть | оставить | оставить |
| Имя файла → нейтральное (`photo_01`) | да | нет | нет |

- Изменил любую галочку — режим становится «Свой». Все категории, включая геопозицию, можно переключать.
- Ручной выбор — по категориям; отдельные теги видны только в подробном просмотре.
- Суффикс `_clean` добавляется **всегда** (`IMG_1234_clean.jpg`, `photo_01_clean.jpg`).
- Оригиналы **никогда** не перезаписываются.
- Выбранный режим запоминается на устройстве.

## Путь пользователя
1. Один вход: перетащить или «Выбрать» (на телефоне сразу открывает галерею). Можно много файлов и папки.
2. Сразу отчёт «что найдено» по каждому файлу. Это же и режим «просто проверить».
3. Кнопка «🧹 Очистить», переключатель режима рядом.
4. После очистки — «было / стало» (файл перечитывается и показывается, что осталось).
5. Получение: кнопка у каждого файла + «Скачать всё» архивом. На телефоне — системное меню «Поделиться» (сохранение прямо в Фото). Без автоскачивания.

## Большие файлы
- Мягкий порог под устройство: компьютер — высокий; Android — по `navigator.deviceMemory`; iPhone/iPad — консервативный (~1 ГБ). Выше порога — «Большой файл, может не получиться. Попробовать?». Выше потолка WASM — вежливый отказ.
- Прогресс по каждому файлу, если обработка дольше ~2 с.
- Точные пороги — по замерам прототипа.

## Скорость
- Первый экран почти ничего не весит; движки не входят в начальную загрузку.
- ExifTool подгружается в фоне сразу после открытия страницы; ffmpeg — только при первом файле, которому он нужен.
- Пакет: маленькие файлы параллельно по числу ядер, большие — по одному.
- Шрифты сабсетятся, без тяжёлых библиотек.

## Дизайн
- Минимализм со вкусом, ощущение **дорогого коммерческого продукта**. Не шаблонный «ИИ-сайт» и не «сайт школьника».
- **Анимации и микровзаимодействия — обязательны**: переходы состояний, живой прогресс, «стирание» категорий в «было / стало», отклик кнопок.
- **Никаких эмодзи в интерфейсе** — выдают «сайт, сделанный ИИ» и рисуются по-разному на разных системах. Только один набор иконок (одна толщина линии, одна сетка), inline SVG, `currentColor`, рядом всегда текстовая подпись. Эмодзи в этом брифе — только для читаемости документа.
- Анимации на transform/opacity/View Transitions. Критерий: 60 fps на эмуляторе бюджетного Android. Уважаем «Уменьшить движение».
- Идеальный UX от 320 px до огромных мониторов; телефон одной рукой.
- До кода интерфейса: исследование референсов в интернете (не по памяти), шрифты с кириллицей, палитра с проверкой контраста WCAG, мудборд с пояснениями, 2–3 живых макета на выбор.

## Тесты
Максимально много, ориентир — реальные сценарии пользователей.
- **Файлы:** сгенерированные с известными метаданными (автотесты в репо), публичные коллекции (скачиваются при тестах), личные файлы владельца (только локально, в `.gitignore`, защита от случайного коммита).
- **Устройства:** симулятор iPhone (вёрстка, Safari, «Поделиться»; памяти не отражает), эмулятор Android 3 ГБ и 8 ГБ, реальные iPhone друзей, облачная ферма перед публичным запуском.

## Безопасность сборки
- Node только **≥ 26.12.1** (CVE-2026-111497, Brotli RCE). Закреплено через `engines` + `engine-strict` — npm откажется работать на уязвимом Node.
- Перед публичным запуском перепроверить статус CVE-2026-111497 и других свежих CVE в цепочке сборки и хостинга.

## Стресс-тест (2026-11-05)
Стенд: `stress/` (страница + сервер только на 127.0.0.1, проверки нативными ffmpeg/sips), запуск `node node_modules/vite/bin/vite.js --config vite.stress.config.ts`, раннер `stress/run.mjs`, генератор злых файлов `stress/make-fuzz.mjs`. Результаты и отчёт — `~/Downloads/unmeta-stress/` (удаляется целиком).
- Наборы: 741 реальный файл с этого Mac (47 форматов, до 15,8 ГБ), 194 тестовых файла ExifTool, 88 «злых» (битые, обрезанные, переименованные, бомбы, GPS в обложках/субтитрах/вложениях).
- Устройства: Mac Chromium и WebKit, Android-эмулятор 3 ГБ/2 ядра, симулятор iPhone 17e, **настоящий Redmi Note 10 Pro** (SD 732G, 6 ГБ, Android 13, Chrome 156).
- Итог: зависаний 0 (на финальном коде), испорченных файлов 0, потерь качества 0 (пиксели/потоки сверены), утечек 0 — остатки в PSD (встроенные документы смарт-объектов) и RAW движок честно показывает как «осталось».
- Скорость, Mac: ≤10 МБ — медиана 0,02–0,08 с; 10–100 МБ — p95 0,6 с; видео до 1 ГБ — ≤2,4 с.
- Скорость, Redmi: фото/документы ≤10 МБ — 0,2–0,8 с (p95 ~2–6 с); 10–100 МБ — ~3 с; видео 135–340 МБ — 6–36 с; **видео ~1 ГБ — 80–160 с**; 2,3 ГБ — вкладка падает (память).
- Найдено и исправлено: каскадное падение ffmpeg после битого файла; деградация ffmpeg в Safari после ~100 файлов (переиспользование + авто-повтор); утечка Blob в воркере (переиспользование каждые 1 ГБ); пустой «очищенный» MOV; GPS в обложках MP3/FLAC/M4A; заголовок в DOCX app.xml; манифест ODS; GeoTIFF; PSD (миниатюра, XMP в слоях); файлы с чужим расширением; контейнер по содержимому (MP4 под .mp3); медленные большие PNG/JPEG/PSD (скелетный путь: 22 с → 0,6 с на Mac, 55 с → 1,5 с на телефоне); медленные MP4 с тысячами пакетов (7,7 с → 0,5 с).
- Пороги размера (`src/ui/limits.ts`) выставлены по замерам: Android 1,5 ГБ (6–8 ГБ ОЗУ) / 0,75 ГБ (меньше), iPhone 1,5 ГБ, компьютер 2,5 ГБ.
- Осталось: ускорить видео ~1 ГБ на телефоне; анимированные GIF ~5 МБ (15 с на Redmi); проверить лимит >2 ГБ на компьютере с реальным выбором файла; живой iPhone; ручная проверка интерфейса на телефоне (галерея, «Поделиться»).
